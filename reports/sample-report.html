HIGH CSP allows 'unsafe-inline' scripts HS-101

Header
content-security-policy
Observed
script-src: * 'unsafe-inline' 'unsafe-eval' data:
Detail
script-src allows 'unsafe-inline', so inline scripts and event handlers execute.
Impact
'unsafe-inline' in a script directive permits inline <script> blocks and event handlers, which is exactly the capability an XSS payload needs — the policy stops being a meaningful mitigation.
Fix
Move inline scripts to external files, or adopt a nonce/hash based strict CSP with 'strict-dynamic' for third-party loaders.
Template
Content-Security-Policy: script-src 'nonce-{RANDOM}' 'strict-dynamic' https:; object-src 'none'; base-uri 'self'
Reference
csp.withgoogle.com/docs/strict-csp.html

HIGH CORS wildcard combined with credentials HS-311

Header

Observed
* + credentials
Detail

Impact
A wildcard origin together with Access-Control-Allow-Credentials: true is rejected by browsers but signals a misconfigured CORS layer; if the wildcard is ever replaced by origin reflection, any site could read authenticated responses.

Recommendations
